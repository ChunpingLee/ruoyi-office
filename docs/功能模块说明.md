# RuoYi Office 功能模块说明文档

> 基于项目源码整理：每个模块的作用、技术框架与开源工具。
> 对应代码版本：`2026.01-SNAPSHOT`（JDK 17，分支 `master-jdk17`）

---

## 一、项目概览

**RuoYi Office（宇擎）** 是基于 **Spring Cloud Alibaba + Spring Boot 3.5** 构建的中小企业全业务办公一体化平台，由 `yudao-cloud`（芋道）脚手架演进而来，在其基础上新增了 OA、HRM、EAM 资产、WMS 仓储等自研业务模块。

### 1.1 整体架构特点

| 特性 | 说明 |
|:---|:---|
| **双部署模式** | 根 pom 定义 `boot` / `cloud` 两个 profile：`boot` 为单体模式（所有模块聚合进 `yudao-server` 单进程启动，跳过 repackage）；`cloud` 为微服务模式（默认，各模块独立打包，经网关 + Nacos 注册发现） |
| **模块化拆分** | 每个业务模块拆为 `xxx-api`（RPC 接口 + DTO，供其它模块 Feign 调用）与 `xxx-server`（业务实现）两个子工程 |
| **多租户 SaaS** | DB / Redis / Web / Security / Job / MQ / Async 七个层面隔离 |
| **全链路权限** | Spring Security 认证 + RBAC 菜单权限 + 基于 SQL 改写的数据权限 |
| **多数据库** | MySQL / PostgreSQL / Oracle / SQL Server / 达梦 / 人大金仓 / OpenGauss，并为 IoT 预置 TDengine 时序库驱动 |

### 1.2 仓库顶层结构

```
ruoyi-office/
├── yudao-dependencies     # Maven BOM，统一管理全部第三方依赖版本
├── yudao-framework        # 技术框架层（18 个自研 Spring Boot Starter）
├── yudao-gateway          # Spring Cloud Gateway 微服务网关（cloud 模式）
├── yudao-server           # 单体启动器（boot 模式入口，聚合各业务模块）
├── yudao-module-*         # 19 个业务模块（见下文）
├── yudao-ui               # 前端工程占位（README 指向独立前端仓库）
├── sql/                   # 多数据库初始化脚本（mysql/pg/oracle/sqlserver/db2 等）
├── script/                # docker-compose 微服务编排、IDEA HTTP 环境配置
└── docs/                  # 项目文档
```

### 2.3 yudao-gateway —— 微服务网关（cloud 模式）

基于 **Spring Cloud Gateway（WebFlux）** 的边界网关：

- `TokenAuthenticationFilter`：校验/解析访问令牌，向下游服务注入登录用户 Header
- `GrayLoadBalancer` + `GrayReactiveLoadBalancerClientFilter`：基于环境标签的灰度路由
- `AccessLogFilter`：访问日志；`CorsFilter`：跨域；`GlobalExceptionHandler`：网关级异常兜底
- `route` 包 + Nacos 实现动态路由；集成 Knife4j Gateway 聚合各微服务 API 文档

### 2.4 yudao-server —— 单体启动器（boot 模式）

单体模式下的唯一入口，默认聚合启用的模块：**system、infra、bpm、oa、hrm、asset、wms**（mall、crm、erp、pay、ai、iot、member、mp、report 等已注释，可按需打开）。本地开发默认端口 `48080`。

## 三、业务模块

> 所有业务模块均遵循统一的工程范式：
> - **拆分**：`yudao-module-xxx-api`（RPC 接口 + DTO）+ `yudao-module-xxx-server`（业务实现）
> - **分层**：`controller/admin`（管理后台接口）→ `service` → `dal/dataobject` + `dal/mysql`（MyBatis Plus）
> - **集成**：跨模块调用统一走 **OpenFeign RPC**（cloud 模式）或本地 Bean（boot 单体模式），BPM 流程状态通过「本地事件 / MQ / Feign 回调」三种方式通知业务模块
> - **公共能力**：多租户、数据权限、Excel 导入导出、操作日志、API 文档开箱即用

### 3.1 yudao-module-system —— 系统管理（平台基座）

**作用**：用户体系与平台治理的核心，所有模块的用户/部门/角色/租户/消息能力来源。

| 功能域 | 说明 |
|:---|:---|
| auth / oauth2 | 登录认证、访问令牌管理、OAuth2 授权（支撑 SSO 单点登录） |
| user / dept | 用户管理、部门管理（组织架构树） |
| permission | 角色 + 菜单 RBAC 权限模型 |
| tenant | 多租户管理、租户套餐 |
| dict / notice | 数据字典、通知公告 |
| sms / mail | 短信渠道与发送记录、邮件账号与发送（站内信 notify） |
| notify | 站内信（WebSocket 实时推送） |
| logger | 操作日志、登录日志 |
| captcha / ip | 行为验证码、IP 库管理 |
| socail | 第三方社交账号绑定（包名拼写沿用上游） |

**技术实现与开源工具**：
- 短信渠道抽象 `SmsClientFactory`：钉钉调试、阿里云、腾讯云、华为云、七牛云
- 邮件：spring-boot-starter-mail + hutool-extra
- 社交登录：**JustAuth 1.16.7**；微信生态：**WxJava（wx-java-mp / wx-java-miniapp）4.7.9**
- 验证码：**Anji-Plus captcha-spring-boot-starter 1.4.0**（行为验证码）
- 站内信推送：`yudao-spring-boot-starter-websocket`

**集成方式**：其它模块经 `AdminUserApi / DeptApi / DictDataApi / TenantApi` 等 Feign 接口获取基础数据；system 自身依赖 hrm-api（员工 ↔ 用户关联）与 infra-api。

### 3.2 yudao-module-infra —— 基础设施（平台基座）

**作用**：研发与运行基础设施：代码生成、文件服务、配置、日志、定时任务管理。

| 功能域 | 说明 |
|:---|:---|
| codegen | 在线代码生成器：读取表结构，生成前后端代码 + SQL + 文档 |
| config | 参数配置（key-value 热配置） |
| db / redis | 数据源配置查询、Redis 监控信息 |
| file | 统一文件服务：上传/下载/权限/预览 |
| logger | API 访问日志、错误码管理、慢 SQL 日志 |
| job | 定时任务管理（对接 XXL-Job） |

**技术实现与开源工具**：
- 代码生成：**mybatis-plus-generator 3.5.15**（解析表结构）+ **Velocity 2.4.1**（模板渲染）
- 文件存储：`FileClientFactory` 支持 5 种后端 —— DB（数据库存储）、本地磁盘、FTP（commons-net）、SFTP（jsch）、**S3 对象存储（AWS SDK v2 2.40.15，兼容 MinIO / 阿里云 OSS / 腾讯云 COS / 七牛等）**
- 文件类型识别：**Apache Tika 3.2.3**

### 3.3 yudao-module-bpm —— 工作流引擎（流程底座）

**作用**：全平台审批流引擎，OA/HRM/WMS/CRM 的所有审批单据由此驱动；提供「仿钉钉/飞书简单设计器 + BPMN 设计器」双模式。

| 功能域 | 说明 |
|:---|:---|
| definition | 流程定义、流程模型（SimpleModel JSON ↔ BPMN 互转）、流程表单、流程分组 |
| task / processInstance | 待办/已办任务、流程实例：审批、驳回、转办、委派、加签/减签、抄送、撤销、超时处理 |
| oa | 内置请假等示例流程 |

**技术实现与开源工具**：
- 工作流引擎：**Flowable 7.2.0**（spring-boot-starter-process / actuator）
- 仿钉钉设计器：SimpleModel 将前端 JSON 转换为 BPMN FlowElement，支持发起人/审批/抄送节点、条件/并行/包容/路由分支、延迟定时器、触发器、子流程（父子流程）
- 多实例审批：会签（任意一人/按比例）、或签、依次审批
- 超时与提醒：BoundaryEvent 定时边界事件实现超时自动提醒/同意/拒绝；流程预测（simulate）可预演执行路径

**集成方式**（见模块内 `README-NOTIFICATION.md`）：流程状态变化支持 **本地事件 / MQ（Redis Stream/RocketMQ）/ Feign 回调** 三种通知通道，可按流程类型配置——单体用本地事件、微服务用 MQ 或 Feign。

### 3.4 yudao-module-oa —— OA 协同办公（自研）

**作用**：日常办公事务线上化，四大功能域全部与 BPM 审批集成。

| 功能域 | 业务对象 | BPM 流程 Key | 说明 |
|:---|:---|:---|:---|
| 用车管理 | Car / CarApplyBill / CarReturnBill | `oa_car_apply_bill`、`oa_car_return_bill` | 车辆档案、用车申请审批、归还登记 |
| 印章管理 | Seal / SealApplyBill | `oa_seal_apply_bill` | 印章登记、用印申请审批、记录追溯 |
| 会议室管理 | MeetingRoom / MeetingRoomBooking | `oa_meeting_room_booking` | 会议室资源、在线预约、前后端双重时间冲突检测、日历视图 |
| 企业云盘 | FileInfo / FilePermission / FileFavorite | 无 | 树形目录（parent_id）、按人员/组织授权（仅查看/可管理）、MD5 去重、收藏；文件实体存 infra 文件服务，DB 只存元数据 |

**技术实现**：MyBatis Plus + BPM API + AdminUserApi/DeptApi/FileApi/DictDataApi（Feign）；会议室模块有专门的页面规范文档（list/info 分页结构，参照印章模块）。

### 3.5 yudao-module-hrm —— 人力资源管理（自研）

**作用**：员工全生命周期管理，「单据 ↔ 档案」分离：审批单独立存储，流程通过后回写员工档案。

| 功能域 | 业务对象 | BPM 流程 Key |
|:---|:---|:---|
| 员工档案 | Employee + 教育/工作/家属关联表 | — |
| 入职管理 | EmployeeEntryBill（含三张明细子表） | `hrm_employee_entry_bill` |
| 转正管理 | EmployeeRegularBill | `hrm_employee_regular_bill` |
| 调动管理 | EmployeeTransferBill | `hrm_employee_transfer_bill` |
| 离职管理 | EmployeeResignationBill | `hrm_employee_resignation_bill` |

**技术实现与开源工具**：
- **XXL-Job 多租户定时任务**（`@TenantJob` 自动遍历租户执行）：
  - `EmployeeResignationByResignationDateJob`（每日 01:00）：到期离职单自动更新员工档案为离职
  - `EmployeeTransferByEffectiveDateJob`（每日 13:00）：到期调动单自动变更员工部门/岗位
- 入职审批通过后一键创建系统账号（联动 system 模块）；对外提供 `EmployeeApi.updateEmployeeByUserId`

### 3.6 yudao-module-asset —— EAM 资产管理（自研）

**作用**：资产全生命周期（采购入库 → 领用 → 维修 → 报废）。

| 功能域 | 说明 |
|:---|:---|
| category | 资产分类（树形结构） |
| info（资产台账） | 资产明细：规格/序列号/厂商/采购单号/入库单号、管理方与使用方（公司/部门/人员）双线、残值率、存放仓库 |
| goods（资产物资） | 物资层管理，与 WMS 联动 |
| lifetime | 资产生命周期轨迹记录 |

**集成方式**：WMS 采购入库审批通过后，经 Feign 调用 `AssetInfoApi.batchSaveInfo` 批量生成资产台账（入库单 → 资产自动建账）。无 BPM 流程、无定时任务。

### 3.7 yudao-module-wms —— WMS 仓储管理（自研）

**作用**：仓库与出入库业务，含采购到入库的完整链路。

| 功能域 | 说明 |
|:---|:---|
| warehousing | 仓库档案（多仓库） |
| purchaseorder | 采购订单 + 明细（BPM 流程 `wms_purchase_order`） |
| purchaseinwarehousing | 采购入库单 |
| goodscommonoperationorder | 通用出入库单（盘点/调拨等场景） |
| goodswarehousingdetail | 入库明细 |

**技术实现亮点**（模块内自建流程集成框架 `framework/security/process`）：
- 流程状态三种接收通道并存：**Feign 回调**（WmsFeignNotificationController）、**本地事件**（Spring ApplicationEvent 监听）、**MQ**（Redis Stream，主题 `bpm.workflow.instance.status.changed`，消息体含租户 ID 支持多租户消费）
- 定义 `IBillBizService` 接口统一实现「单据审批状态回写」的扩展点
- 入库完成 → Feign 调用 asset 模块批量生成资产台账

### 3.8 yudao-module-crm —— CRM 客户关系管理

**作用**：销售全流程：线索 → 客户 → 商机 → 合同 → 回款。

| 功能域 | 说明 |
|:---|:---|
| clue / customer / contact | 线索（转化/分配）、客户公海与私海、联系人 |
| business | 商机跟进与阶段推进（销售漏斗） |
| contract | 合同管理，对接 BPM 审批 |
| receivable | 回款计划与回款记录、款项明细 |
| product / followup | 产品目录、全类型对象的跟进记录（日程化） |
| permission | CRM 专属「团队数据权限」：按成员/部门/岗位配置查看/编辑/删除/导出权限 |
| statistics | 销售漏斗、业绩、客户画像等报表 |

**技术实现**：MyBatis Plus + BPM（合同审批）+ system（用户/部门）；Excel 报表导出用 FastExcel。

### 3.9 yudao-module-erp —— ERP 进销存

**作用**：采购/销售/库存/财务一体化。

| 功能域 | 说明 |
|:---|:---|
| product | 产品管理（分类、单位） |
| purchase | 采购订单、采购入库、采购退货 |
| sale | 销售订单、销售出库、销售退货 |
| stock | 库存查询、其它出入库、库存盘点、库存明细 |

### 3.11 yudao-module-pay —— 支付中心

**作用**：独立支付中台。统一支付/退款/转账抽象，向上屏蔽渠道差异；设计上服务于**任何**需要收付款的业务模块（不限于商城）。定位模型：商户 → 支付应用（`pay_app`，按 `appKey` 标识业务方）→ 支付渠道（`pay_channel`，每应用按需开通）。

#### 3.11.1 功能域

| 功能域 | 说明 |
|:---|:---|
| app | 支付应用管理：每个业务方注册一个应用（appKey），各自配置支付/退款/转账三个回调地址（`orderNotifyUrl` / `refundNotifyUrl` / `transferNotifyUrl`） |
| channel | 支付渠道配置：共 14 种（`PayChannelEnum`）——微信 6 种（公众号 JSAPI / 小程序 / APP / Native / WAP / 付款码）、支付宝 5 种（PC / WAP / APP / 扫码 / 条码）、**钱包支付**、**mock 模拟支付**（本地联调免渠道） |
| order | 支付单：统一订单模型，待支付→成功/失败全状态流转，支持改价（`updatePayOrderPrice`，应付价与实付价分离） |
| refund | 退款单：业务方经 `PayRefundApi` 发起，渠道回调驱动状态 |
| transfer | 转账单：企业付款场景（如分销提现），`PayTransferApi` |
| notify | 回调通知：见 3.11.3 |
| wallet | 用户钱包：余额、交易流水（6 种业务类型：充值/充值退款/支付/支付退款/更新余额/转账）、**充值套餐**（`payPrice` + `bonusPrice` 充值赠送）；钱包本身也是一种支付渠道，可用余额付款（余额不足自动组合微信/支付宝） |
| demo | 官方接入示例：`PayDemoOrderController` / `PayDemoWithdrawController`，照抄即可完成接入 |

#### 3.11.2 技术实现与开源工具

- SDK：**alipay-sdk-java 4.40.607**、**weixin-java-pay 4.7.9**，经 `PayClientFactory` 统一工厂管理，渠道可插拔扩展
- 对外 RPC（Feign，`yudao-module-pay-api`）：`PayOrderApi`（创建/查询/改价）、`PayRefundApi`、`PayTransferApi`、`PayWalletApi`（余额变更）

#### 3.11.3 回调通知机制（可靠性核心）

1. 渠道异步回调支付中心 → 更新支付单状态 →（**事务提交后**）异步生成 `PayNotifyTask`
2. HTTP POST 业务方按 appKey 配置的回调地址，消息体为 `PayOrderNotifyReqDTO`
3. 回调失败由 `PayNotifyJob`（XXL-Job）按**衰减间隔补偿重试**，有最大通知次数与并发幂等防护（通知版本号校验）

#### 3.11.4 业务方接入三步（任何模块通用）

1. 注册支付应用（appKey）+ 开通渠道 + 配置回调 URL；
2. 下单时 Feign 调 `PayOrderApi.createOrder(appKey, merchantOrderId, price, subject, expireTime...)` 获取支付单号，前端拉起收银台；
3. 提供一个 `@PermitAll` 回调接口接收 `PayOrderNotifyReqDTO`（内部校验商户单号与支付单一致性防伪造，参考 demo 的 `/update-paid`）。

#### 3.11.5 当前仓库实际接入方

| 接入方 | 用途 | 调用的 API |
|:---|:---|:---|
| mall-trade（**唯一业务接入方**） | 订单支付、售后退款、分销佣金提现 | PayOrderApi / PayRefundApi / PayTransferApi |
| pay 自身 | 钱包充值（充值本质也是一笔支付单） | PayOrderApi |
| demo 示例模块 | 接入样例 | PayDemoOrderController |

> 注意：会员充值、OA 缴费等场景同样可复用，但目前仓库内无其它模块接入；且 `yudao-server` 默认**未启用** pay 模块（pom 依赖注释状态），启用需打开 `yudao-module-pay-server` 依赖并初始化 `pay_*` 表。
